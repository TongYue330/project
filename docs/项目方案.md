（1）个人项目方案
表2-12 个人项目方案概览

项目	内容
项目名称	课程作业AI答疑助手
核心用户流程	学生上传题目（拍照或文字）→ AI识别并生成分步骤解答 → 学生查看解答，可针对某步追问 → 系统记录历史
技术栈	Python + Flask（后端）、HTML/CSS/JS（前端）、通义千问API（AI能力）、SQLite（本地记录存储）

（2）MVP功能范围
表2-13 纳入MVP的功能

编号	功能	说明
F1	拍照上传题目	支持上传jpg/png格式图片，调用多模态模型识别题目内容
F2	文字输入题目	提供文本输入框，支持纯文字题目提交
F3	AI生成分步骤解答	调用通义千问API，返回包含解题步骤的完整解答

F5	历史记录查看	按时间倒序展示用户之前的提问和解答
F6	AI不确定时给出提示	当模型置信度低或无法识别时，显示“AI生成，仅供参考”提示
来源：个人分析。

（6）过程记录
调研过程：参考了课程周期（第2—17周）和个人可投入时间，也看了豆包和千问的功能范围作为对比。

分析过程：最初设想的功能包括拍照上传、AI解答、错题本、知识点推荐和用户注册。但调研后发现错题本和知识点推荐已是大厂标配，个人开发难以超越。用户注册登录在课程周期内也不必要。因此删减为只保留核心答疑流程。分阶段计划按每周可投入时间制定，把功能拆解成可运行的小步骤，并预留删减预案。

取舍：删掉了错题本、知识点推荐、用户注册登录、移动端App、社交分享五个模块。技术栈上前端从React改为原生HTML/CSS/JS，降低开发风险。

需求变化：MVP范围从最初的大而全，收缩到“拍照/文字上传→AI分步骤解答→针对某步追问→历史记录”这一条核心链路。
